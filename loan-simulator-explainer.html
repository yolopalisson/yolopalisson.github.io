Capitec Loan Simulator

A responsive, compliance-first loan simulation tool that guides customers through dynamic credit tiers and delivers indicative estimates with an accessibility-first mindset.

Start the Walkthrough
01 · The Strategy

From Generic Calculator to Capitec Product

The original brief asked for a standard eligibility calculator. I re-engineered it to reflect the strict compliance and brand guidelines of Capitec Bank.

🛡️

Compliance First

Removed the self-reported credit score input. In a real bank, credit scores must be queried securely from a bureau. The mock API simulates this check at submission.

🎨

Brand Identity

Implemented Capitec's exact color palette (#0F204B Corporate Blue), Inter typography, and modern UI elements like frosted glass and squircles.

02 · Deliverable

What I Built

A full loan application flow; from dynamic product selection to an indicative amortisation schedule, fully compliance-aware.

📝

Dynamic Input Form

Personal, financial, and loan details. The form automatically adapts its min/max validation rules based on the selected NCA credit tier.

🛡️

Compliance Notice

A mandatory notice replaces the self-reported credit score input, informing users that a secure bureau check will be performed.

⚖️

Indicative Verdict

Approval likelihood, risk category, and a clear "indicative estimate only" disclaimer wrapped around the results.

💰

Indicative Offer

Recommended amount, indicative interest rate, estimated monthly repayment, and total cost over the term.

📈

Affordability Analysis

Disposable income, DTI, LTI, and an affordability score, visualised with progress bars. Includes a real-time warning if expenses exceed income.

📅

Payment Schedule

Full month-by-month amortisation. Table on desktop, cards on mobile. Expandable. Hidden entirely if the user is not eligible.

03 · Architecture

Backend-Ready Frontend

Built using a strict 3-layer architecture. Swapping the mock for a real Capitec backend is a one-line change in the API client.

1

UI Layer

React components. Focused purely on presentation, accessibility, and interactive forms driven by React Hook Form + Zod.

2

State Layer

TanStack Query manages caching, API loading states, error resilience, and mutations.

3

API Layer

Mock Service Worker (MSW) intercepts standard network requests, powering both the dev environment and the automated test suite.

05 · Product Logic

Dynamic Credit Tiers

The form adapts its validation rules dynamically based on the selected NCA credit tier. Minimum and maximum boundaries update instantly.

⚡

Short-Term

  • Max R8,000
  • Max 6 months
  • Higher interest range
💳

Unsecured

  • R8,001 – R250k
  • 12 – 84 months
  • Standard personal loan
🚗

Secured

  • R250k+
  • Asset-backed
  • Lower interest rates
06 · Compliance

Indicative Language

Banking regulations require clear communication that estimates are not binding offers.

⚖️

The Disclaimer

Every result is wrapped in a prominent amber disclaimer: "The results below are an indicative estimate only. Your final offer is subject to a full credit and affordability assessment."

Labels were also changed: "Recommended Loan" became "Indicative Offer", and "Interest Rate" became "Indicative Interest Rate".

07 · UX Edge Cases

Handling Failure States

A production-grade app must handle things going wrong gracefully.

🚫

Not Eligible State

If a user is declined, we never show a payment schedule for a loan they can't get. Instead, the UI hides the offer and renders a "How to improve your chances" card with actionable advice.

📉

Expenses > Income

If monthly expenses exceed income, a real-time red warning appears instantly in the form, preventing the user from submitting a guaranteed decline.

📡

API Resilience

If the initial API load fails, the app displays a dedicated "Connection Error" screen with a "Try again" button to refetch the product data.

♿

Accessibility (ARIA)

Changing the credit tier resets the form. An invisible aria-live region announces the new min/max limits to screen readers so they aren't confused by the sudden change.

08 · Testing

Unit

2

Component

3

Integration

09 · Ship

Deployment Pipeline

Local → GitHub → Vercel → Live URL.

  • Dockerfile — multi-stage build, Nginx runtime, SPA fallback
  • vercel.json — SPA rewrites so client-side routing works on refresh
  • VITE_ENABLE_MSW=true — env var that activates MSW in production builds
  • .gitignore — excludes node_modules, dist, env files
  • Auto-deploy — every push to main triggers a Vercel rebuild
10 · Reasoning

Key Decisions & Why

◈

MSW, not hardcoded data

Exercises the real network layer. Testable. Swaps to a real backend in one line.

◈

API-driven validation

Business rules live in one place. Backend changes ripple forward automatically without a frontend deployment.

◈

Compliance over convenience

Removed the self-reported credit score. Banks must query bureaus. The mock API simulates this securely at submission.

◈

Accessibility first

Not bolted on. Every component was designed with keyboard and screen readers in mind, including dynamic ARIA announcements.
